## 统计口径

从实际启用时开始累计，不恢复历史访问。只统计自愿同意的浏览器，按随机标识去重；同浏览器同页面 30 分钟内刷新只计一次。浏览器数不是精确人数，也无法保证完全排除自动化请求。

本地预览只读取聚合数据，不上报访问。正式网站进入「观测」可允许或关闭当前浏览器统计。记录仅包含随机标识和页面路径，不包含搜索词、网址参数、账号、IP 或 User-Agent；平台自身服务日志由平台处理。

## 数据库检查说明

安全检查没有发现未启用 RLS 的新增表。以下提示已核对用途：

- 两个统计 RPC 有意允许游客调用 `SECURITY DEFINER` 函数：只公开聚合值或写入经过路径校验、限频和去重的计数，固定空 `search_path`，无任意 SQL 参数。个体记录仍在私有 schema，客户端不能直接读取。[匿名调用提示](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable)、[登录用户调用提示](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)。
- 原有 Auth 的泄露密码检查未开启，本次未改动套餐或账户策略。[官方说明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。
- 新表暂无查询历史时，部分索引会被列为 unused index 提示；保留支持消息排序、回复和限流所需索引。[索引提示](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)。

## 发布流程与发布后核对

代码提交、推送到 main 后，GitHub Actions 的 `Deploy blog to GitHub Pages` 会执行依赖安装、测试、构建和部署。只有部署成功后才视为上线完成。

发布后检查正式域名的首页、留言实时连接和「观测」数据；使用自己的账户进一步体验发送、回复和删除。新增文章仍需按原流程登记到 `supabase/seed-posts.sql` 对应后端表，才可开放该文章的评论。
