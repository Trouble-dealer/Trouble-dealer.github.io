## 已包含的自动检查

`npm run build` 会执行 Astro 类型检查、静态构建和 `scripts/verify-build.mjs`。后者检查构建后的站内链接、图片与脚本资源、目录锚点、子路径前缀、搜索结果路径、RSS 条目数量和草稿过滤。

`node --test scripts/search.test.mjs` 检查中文正文搜索、英文大小写、多关键词、排序、特殊字符和摘要截取。它使用 Node.js 24 的 TypeScript 类型擦除能力，工作流也采用 Node.js 24。

`npm test` 还会在 PGlite 的 PostgreSQL 中测试实际 SQL 迁移和行级权限，总计 15 项。账号和评论的真实邮箱验收按第 06 份文档执行；无需在 SMTP 配好前尝试访客注册。

检查不会访问和判定每个第三方链接的长期可用性，也不能替代真实账号下的 GitHub Pages / DNS 验证。

## 为什么网页上传后是 404？

按顺序检查：仓库是否公开 → Source 是否是 GitHub Actions → 工作流是否包含在 `.github/workflows/deploy.yml` → 是否运行成功 → 打开的地址是否正确。

查看 Actions 中首个失败的步骤。如果失败在 Configure Pages，通常先检查仓库 Pages 设置；若失败在安装依赖，打开日志看具体网络或依赖提示。可将相关错误日志发给我，不需要提供登录凭证。

## 页面有内容但没有样式，或搜索失败

常见原因是路径前缀不匹配。例如部署到 `/blog/` 却生成了根目录路径。默认配置下 CI 会自动推导路径；如果手动填了正式网址，就要同时检查 `base`。

不要在本地用 `file://` 直接打开构建文件。请使用 `npm run preview` 提供的 HTTP 地址。

## 修改文章后预览没变化

`npm run dev` 会监听文件更新。`npm run preview` 只查看上次构建的 `dist`，需要先重新 `npm run build`。

线上则要等待新的 Actions 部署完成。必要时硬刷新页面，或在新的浏览器窗口验证。

## 搜索不到刚写的文章

检查是不是 `draft: true`；确认修改已构建并上线。搜索索引随同一批构建产物生成，没有独立的索引服务器需要维护。

## 本地构建报 Astro telemetry 目录写入权限错误

在当前 PowerShell 终端中执行后再重试：

```powershell
$env:ASTRO_TELEMETRY_DISABLED='1'
npm run build
```

这只关闭本次命令环境的 Astro 遥测。双击预览脚本时已经自动设置。普通个人电脑通常不受本次开发沙箱的目录限制影响。

## 文章里能不能放私密资料？

这个方案的仓库和网站按公开方式发布。草稿也只是不上网页，源文件仍然公开。因此请将真正的私密资料留在项目之外。

## 我想换成 Firefly 的全部功能

当前项目是按参考风格独立编写的轻量博客。Firefly 的更多组件、主题配置、扩展服务不是这里的既有功能。如果后续决定迁移到原版 Firefly，可以保留 Markdown 内容，再逐项调整元数据与路径；需要另做迁移和验证。
