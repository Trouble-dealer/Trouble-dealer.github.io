# 绑定自己的域名

> Elio 当前选定 jy.遮阳帽.space，在阿里云只需添加 jy 的 CNAME 指向 Trouble-dealer.github.io。GitHub Custom domain 使用等价 ASCII 写法 jy.xn--wut303ivvd.space。代码已配置该地址。无需修改根域名 A 记录，下面的根域名方案仅供理解，不是本次需要操作的步骤。

先确保默认 `github.io` 地址已经能打开，再操作这一份教程。域名在哪里购买都可以，关键是能管理它实际使用的 DNS。

下面示例中的 `example.com` 必须换成你的真实域名，`alice` 必须换成 GitHub 用户名。

## 先决定用哪个地址

| 你想要的博客地址 | 类型 | 常见 DNS 记录 |
| --- | --- | --- |
| `https://example.com` | 根域名 | `@` 的 A 记录 |
| `https://blog.example.com` | 子域名 | `blog` 的 CNAME |
| `https://www.example.com` | www 子域名 | `www` 的 CNAME |

如果根域名正在用于其他网站，优先选择 `blog.example.com`，这样可以保留已有网站。域名注册商和 DNS 服务商可能不同，例如域名在阿里云购买，但 Nameservers 指向 Cloudflare，此时应去 Cloudflare 修改记录。

## 第一步：建议先在 GitHub 验证域名所有权

这一步不是所有情况下的上线前置条件，但可以降低域名被其他 GitHub 仓库占用的风险。

1. GitHub 右上角头像 → **Settings → Pages**（这一步是个人账号设置）。
2. 选择 **Add a domain**，按提示输入域名。
3. GitHub 会给出一条 TXT 验证记录及唯一的值。
4. 在 DNS 管理页面添加它，记录名和值以 GitHub 当次显示的内容为准。
5. 回到 GitHub 点 **Verify**。验证通过后，保留 TXT 记录。

不要把这个 TXT 值写成教程中的示例字符串；每个账号生成的值不同。

官方说明：[验证自定义域名](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages)。

## 第二步：修改博客的正式网址

编辑项目根目录 `site.config.mjs`：

```javascript
url: 'https://blog.example.com',
base: '/',
```

如果你选的是根域名，就填 `https://example.com`。

`url` 不要带文章路径、账号密码、端口或 `?` 参数。即使仓库叫 `blog`，启用独立域名后 `base` 也使用 `/`。

提交并推送修改。发布脚本会自动生成对应域名的 `CNAME` 构建文件，并将 RSS、站点地图和文章规范链接改到新地址。仅修改这个文件不会替你完成 DNS 或 GitHub 设置。

## 第三步：保存 GitHub Pages 的自定义域名

打开博客**仓库**：

1. **Settings → Pages → Custom domain**。
2. 填 `blog.example.com` 或 `example.com`，不要加 `https://`，不要加路径。
3. 点 **Save**。

保存 Custom domain 后，再修改 DNS。DNS 检查尚未通过时可以继续下一步。

## 第四步：设置 DNS，按选定的地址选择一种

### A. 使用 blog.example.com 或 www.example.com

新增一条 CNAME：

| 字段 | blog 子域名的值 |
| --- | --- |
| 类型 | CNAME |
| 主机记录 / 名称 | `blog` |
| 目标 / 内容 | `alice.github.io` |
| TTL | 自动或服务商默认 |

如果用 `www.example.com`，主机记录改为 `www`。

目标只写 `用户名.github.io`，不要加 `https://`，不要加仓库名或尾部路径。CNAME 的目标不是 `github.com`。

同一个主机名不能同时保留冲突的 A / AAAA / CNAME。先核对用途，再替换这个主机名的冲突记录；不要删除整个域名下的其他记录。

若使用 Cloudflare，初次配置建议使用 **DNS only / 仅 DNS（灰云）**，便于 GitHub 检查和签发证书。

### B. 使用根域名 example.com

添加以下 4 条 A 记录，主机记录通常是 `@`：

| 类型 | 主机 | 目标 |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |

这些地址已在本次准备教程时与 GitHub 官方文档核对。未来若 GitHub 更改配置，以官方文档为准。

可选的 IPv6 AAAA 记录：

| 类型 | 主机 | 目标 |
| --- | --- | --- |
| AAAA | @ | 2606:50c0:8000::153 |
| AAAA | @ | 2606:50c0:8001::153 |
| AAAA | @ | 2606:50c0:8002::153 |
| AAAA | @ | 2606:50c0:8003::153 |

不会使用 IPv6 时，可以先只添加 A 记录；但不要保留指向其他旧服务器、与此站冲突的 AAAA。

如果还希望访问 `www.example.com` 时跳转到根域名，再添加 `www` CNAME 指向 `alice.github.io`。GitHub 官方建议同时配置根域名与 www，以实现其支持的重定向。

**不要新增通配符 `*` 解析；不要动邮箱使用的 MX / SPF / DKIM 等记录。**

## 第五步：等待解析与 HTTPS

回到仓库 **Settings → Pages**：

1. 等待 DNS check 成功。
2. 等 GitHub 为域名签发证书。
3. **Enforce HTTPS** 可选后将其勾选。
4. 使用 `https://` 打开正式地址。

DNS 与证书可能需要一段时间，DNS 更改有时最长约 24 小时传播。暂时不能勾选 HTTPS 时，不要通过关闭证书验证来绕过；先核对解析与 GitHub 状态。

## 第六步：检查地址是否统一

- 首页、文章、分类、搜索都能打开。
- 打开 `https://你的域名/rss.xml`，里面的原文链接使用真实域名。
- 打开 `https://你的域名/sitemap.xml`，里面没有 `example.com` 或多余的 `/blog/`。
- 若有 www，检查它按预期重定向。
- 手机移动网络下也尝试访问一次，排除本机 DNS 缓存影响。

Windows 可做基础 DNS 检查：

```powershell
nslookup blog.example.com
nslookup example.com
```

这只是查询，不会更改 DNS。将示例域名换成你的真实域名。

## 常见问题

**域名买好了，是否就已经能访问？**

还不行。需要网站发布成功、GitHub 保存 Custom domain、DNS 指向正确目标，以及证书准备完成。

**能否绑定多个互不相关的域名到同一个 Pages 站点？**

本教程按一个正式域名配置。www 与根域名的配套重定向按 GitHub 官方支持处理；其他域名的跳转需要另外设计。

**需要购买云服务器或数据库吗？**

当前静态博客不需要。域名原有续费仍然存在，Pages 免费使用受 GitHub 的产品限制和政策约束。

**大陆地区访问会不会不稳定？**

访问效果受当地网络与 GitHub 连接状况影响。绑定域名不会改变网站实际由 GitHub Pages 托管这一点，也不能保证改善所有网络的速度。
