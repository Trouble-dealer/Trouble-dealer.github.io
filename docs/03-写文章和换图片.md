# 写文章、修改资料和替换图片

> 当前项目已个性化为具野 · Elio，邮箱注册和评论采用 Supabase，代码与数据库已完成，等待 SMTP 和 Auth 跳转配置。账号启用以《06-Elio的注册评论启用步骤.md》为准。

## 修改个人资料

编辑项目根目录 `site.config.mjs`。优先改这些字段：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| title | 博客名 | `小林的博客` |
| subtitle | 副标题 | `记录生活与所学` |
| description | 搜索引擎与分享用简介 | `关于编程、阅读和日常的个人记录。` |
| author | 公开昵称 | `小林` |
| bio | 侧栏简介，`\n` 表示换行 | `写代码，也写生活。` |
| url | 正式 HTTPS 域名 | `https://blog.your-domain.com` |
| base | 网站路径前缀 | 独立域名和用户主页填 `/` |
| github | 公开 GitHub 网址，空值隐藏 | `https://github.com/用户名` |
| email | 公开邮箱，空值隐藏 | 使用你愿意公开的地址 |
| postsPerPage | 首页每页文章数，正整数 | `4` |

`hero` 中可改首页横幅的英文小字、主标题、说明、背景色和图片。关于页面的正文可编辑 `src/pages/about.astro`，它目前是通用起步文案，并不是已确认的个人经历。

## 新建文章

在终端中运行：

```powershell
npm run new -- my-first-post "我的第一篇文章"
```

会生成 `src/content/posts/my-first-post.md`，默认 `draft: true`。文件已存在时命令会拒绝覆盖。

也可以手动新建 `.md` 文件，推荐小写英文文件名，用短横线连接单词。文件名会成为文章网址的一部分，发布后尽量不要随意改名，以免旧链接失效。

文章结构示例：

```yaml
---
title: '我的第一篇文章'
description: '这一篇主要想分享什么。'
published: 2026-10-25
updated: 2026-10-26
category: '生活随笔'
tags: ['记录', '写作']
draft: false
pinned: false
color: sage
cover: ''
---
```

在第二条 `---` 后面写正文，例如：

```markdown
这是一段正文。

## 第一个话题

这是一段新的说明。

### 一个小细节

- 列表项目
- 另一个项目
```

标题中含有单引号时，可以改用双引号或用两个单引号转义。元数据缩进与标点有误时，构建会明确报错，修正后再发布。

### 字段规则

- `published` 是发布时间，用 `YYYY-MM-DD`。不提供时分秒会按日期处理，展示时使用上海时区。
- `updated` 可省略；正文有实质修改时可以补上。
- `category` 每篇一个，默认“随笔”。使用简短名称，避免 `/`、`#`、`?` 这类路径字符。
- `tags` 可多个，尽量复用已有名称；标签同样避免路径特殊字符。
- `draft: true` 不生成文章页，不进入搜索、统计、RSS 和站点地图。
- `pinned: true` 只影响首页排列；归档仍按发布时间排列。
- `color` 可选 `sage`、`sand`、`lavender`、`blue`、`rose`。
- `cover` 留空显示纯色，有图片后填写站内路径。

草稿不是私密空间，公开仓库仍能看到其 Markdown 源文件。本项目也不提供定时发布：非草稿文件会在每次构建时发布，未来日期不会自动成为定时任务。

## 替换头像和横幅

先将图片放到 `public/images/`。建议用英文文件名，WebP / JPG / PNG 都可以。

例如保存：

```text
public/images/avatar.webp
public/images/banner.webp
public/images/first-post.webp
```

修改 `site.config.mjs`：

```javascript
avatar: '/images/avatar.webp',
// 在 hero 对象中修改：
image: '/images/banner.webp',
```

路径中不要写 `public`。也不要填写 `D:\...` 这种本机路径，网站访问者读不到它。

- 头像建议至少 256 × 256，正方形。
- 横幅建议宽幅，例如 1920 × 700，中心区域保留主体。
- 封面建议约 1200 × 800，展示时会裁切，重要内容别放最边缘。
- 只上传你自己拥有或已获许可的图片，尽量先压缩体积。

## 给文章加封面

在该文章元数据中填写：

```yaml
cover: '/images/first-post.webp'
```

首页卡片和正文都会使用它。留空则继续用 `color` 对应的纯色。

## 在正文中插入图片

用户主页或独立域名部署时，可以写：

```markdown
![描述图片内容的替代文字](/images/first-post.webp)
```

**如果使用 `github.io/blog/` 这种子路径部署**，原生 Markdown 的 `/images/…` 不会自动补上 `/blog/`。需要写完整子路径，例如 `/blog/images/first-post.webp`；或者先绑定独立域名再大量添加图片。封面、头像、横幅由本站组件统一生成地址，会自动适配 base。

构建链接检查会发现正文图片路径不存在的情况。

## 修改友链

编辑 `site.config.mjs` 的 `friends` 数组：

```javascript
{
  name: '朋友的博客',
  url: 'https://真实网址',
  description: '一句真实的站点介绍。',
  color: '#dce9e3',
},
```

删除不需要的条目即可。当前列出的 Firefly、Hyde Blog 和 Astro 是参考与工具链接，不表示已经互换友链。

## 关于评论、统计和后台

当前读者登录和评论使用真实 Supabase Auth / 数据库。发信测试前不会开放注册或提交入口，详见第 06 份文档。没有点赞、访问统计或在线文章编辑器。

博客写作仍是编辑本地或 GitHub 中的 Markdown；读者账户不具备文章管理权限。评论审核在 Supabase 控制台完成。

新增文章后，构建会更新 supabase/seed-posts.sql；将它应用到 Supabase 后才开放新文章的评论提交。

## 每次发布

1. 写完文章，改为 `draft: false`。
2. `npm run dev` 看效果。
3. `npm run build` 检查代码和全部站内资源。
4. 提交并推送，等待 Actions 成功。
5. 在线上重新打开文章和搜索验证。

起步文章都在 `src/content/posts/`，可以改写、删除，或将 `draft` 改为 `true` 隐藏。不建议在还没看过实际效果前一次性删光。
