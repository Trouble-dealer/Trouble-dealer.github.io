GitHub Pages 可以把仓库中的静态文件发布成网站。对个人博客来说，文章先在构建阶段生成 HTML，再由 Pages 提供访问，不需要自己购买服务器。

## 先区分三个东西

**GitHub 账号**用于登录和管理项目；**仓库**保存博客源代码；**GitHub Pages**是仓库设置中的网站发布功能。

Pages 不需要再注册一个独立账号。使用免费方案时，为这个博客创建公开仓库，是最直接的做法。

## 选择仓库名称

如果希望默认地址是 `https://你的用户名.github.io/`，仓库应命名为 `你的用户名.github.io`。

如果仓库叫 `blog`，默认通常是 `https://你的用户名.github.io/blog/`，构建时也需要相应的路径前缀。本项目的发布流程会在没有填写自定义域名时，根据仓库名自动计算它。

## 启用自动构建

上传源代码后，在仓库的 **Settings → Pages → Build and deployment** 中，将 Source 选为 **GitHub Actions**。

项目内的工作流依次执行：

1. 安装锁文件中记录的依赖。
2. 检查文章与页面代码。
3. 生成静态文件并检查站内链接。
4. 上传构建产物，交给 Pages 发布。

文章更新后，把修改推送到 `main` 分支，就会再次触发构建。

## 绑定自己的域名

自定义域名涉及两处配置：GitHub Pages 的 Custom domain，以及域名服务商的 DNS。

还需要同步修改博客配置中的网址，这样 RSS、规范链接和站点地图才会指向自己的域名。DNS 的记录值取决于使用根域名还是子域名，应按照官方说明填写。

## 检查发布结果

发布成功后，至少打开一篇文章、一个分类页，以及搜索、RSS。用手机再检查一次导航和正文阅读。

本项目文件夹中的 `docs/01-部署到GitHub-Pages.md` 提供了更详细的操作步骤；域名配置在 `docs/02-绑定自己的域名.md`。
